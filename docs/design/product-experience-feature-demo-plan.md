# OptiSpray 产品体验功能演示方案

## 设计目标

让访客沿着一条可操作的产品流程，看懂环境信息如何进入任务规划、无人机如何执行喷洒、平台如何记录结果。菜单中的每个入口都要说明一个独立问题，并有对应的画面或交互；不能只更换标题、复用同一张部件特写。

页面保留五个现有菜单分组和 18 个入口。工程解释设计构造；产品体验页解释部件如何工作、喷洒如何发生、作业如何规划和回顾。产品页不增加“实测 / 模型 / 示意”来源标签。数据、功能、价格和服务范围只使用项目网站与 Dashboard 已有资料。

产品页的核心信息放在画面上方，功能入口在左侧。点一次即播放整章，播放结束后再点同一入口可以重播。步骤说明与进度在底部，传感器读数用约一秒的半透明信息框呈现。

环境信息 → 作业规划 → 硬件执行 → 喷洒过程 → 作业回顾 → 下一次规划

## 各菜单内容设计

### 产品体验

#### 1. Overview

- **要让访客看懂：** 环境信息、路线选择、喷洒执行和作业回顾是同一流程。
- **当前差距：** 有四个跳转按钮，没有连续播放，也没有把同一任务的前后状态串起来。
- **画面与交互：** 设计 12 秒可暂停流程。第 0–2 秒显示全景和无人机；第 2–4 秒聚焦环境读数；第 4–6 秒沿同一地块亮出航线；第 6–9 秒由喷嘴进入液滴轨迹；第 9–11 秒显示同一案例的沉积进度；第 11–12 秒转到 Dashboard 报告入口。每个阶段均可点按进入对应菜单。场景播放不自动替换用户当前选择的 Dashboard 任务。
- **完成条件：** 流程每步使用对应菜单的数据和动画；右上说明卡不压住菜单按钮，无人机和喷雾主体保持可见；重播从统一初始状态开始。

#### 2. Product advantages

- **要让访客看懂：** 规划、喷洒观察、报告回顾分别解决什么问题。
- **当前差距：** 当前三条优势是静态文字，没有在本页呈现相应依据。
- **画面与交互：** 三张卡分别跳到已有的 Plan A/B 航线对比、液滴/沉积章节、Dashboard 报告与历史。路线卡只使用同一地块的已有覆盖、航段和计划用时；沉积卡只使用已有 Plan A 结果；不添加推断的收益或作业效果。
- **完成条件：** 每条优势都能一步到达对应画面；数值与原始页面一致；没有依据的结论不出现在卡片或旁白中。

### Intelligent Hardware

#### 3. Wind sensor

- **要让访客看懂：** 超声波探头如何测出风向和风速，以及读数如何传给控制器。
- **当前差距：** 有探头、脉冲与 RS485 步骤，但画面只报告风速，方向和下一环节没有接上。
- **画面与交互：** 复用现有四个探头近景。依次显示整机位置、探头分离、两组往返脉冲、当前案例风向箭头、RS485 信号到现有控制模块。随后镜头落到田块，沿案例已有的西向东风箭头指向航线和喷洒区域。只播放当前案例条件，不凭空生成风速变化。
- **参考：** [Gill WindSonic](https://gillinstruments.com/products/wind-sensors/windsonic/) 展示对向超声波测风、风速/风向输出和 RS485 接口，可作为传感原理与产品外形参考，不代表项目选用了该型号。
- **完成条件：** 可单步播放、重播、重置；无人机外观不变；风向和 Dashboard 案例方向一致。

#### 4. Temperature & humidity

- **要让访客看懂：** 环境温度和湿度从哪里进入作业信息。
- **当前差距：** 只有两项静态读数，没有传感器特写，读数也没有连接到 Dashboard 环境卡。
- **建模与动画：** 新增一个小型通风罩与内部传感板作为局部特写；只在拆分镜头中出现，不指定飞机装机点。播放环境进入护罩、传感板采集、温度/湿度读数依次传入 Dashboard 条件卡。读数沿用 Skagit 案例。现有网站没有把这两项输入实时联动到当前三维液滴结果的路径，因此本章节不改变液滴轨迹。
- **参考：** [Bosch BME280](https://www.bosch-sensortec.com/en/products/environmental-sensors/humidity-sensors-bme280) 是温度、湿度和气压组合元件，可借鉴板级器件和外壳比例；它不是项目已选元件。
- **完成条件：** 读数与案例一致；没有新增湿度影响沉积的数值动画；部件没有出现在无人机总览的固定装机位置。

#### 5. Light sensing

- **要让访客看懂：** 照度如何被采集并进入设备数据。
- **当前差距：** 入口只有一句照度字段说明，没有部件或采集过程；项目没有照度案例读数。
- **建模与动画：** 用小型电路板和单一光学开口做局部特写，表现光线进入窗口、光敏器件转换、数据线接到 Dashboard 的照度字段。字段没有来源读数时不显示数字、不设阈值、不触发作业建议；不指定飞机安装位置。
- **参考：** [Texas Instruments OPT3001](https://www.ti.com/product/OPT3001) 的光学开口、板级器件和数字接口可作形态参考，不把它写成项目选型。
- **完成条件：** 画面解释“采集并传递”即可，不新增基于照度的作业规则或指标。

#### 6. GPS positioning

- **要让访客看懂：** GPS 定位输出的位置如何沿选定航线更新。
- **当前差距：** 原动画把重点放在接收器拆装，并让整架无人机随产品介绍进度移动，容易被误解成实时飞行遥测。
- **建模与动画：** 先用苹果产品展示式设备特写标出现有定位接收部件；随后切到项目已有 Plan A/B 航线视图，只让位置游标沿选定路线更新。游标绑定本页播放进度，不显示偏差距离、定位精度或飞控状态。
- **参考：** [u-blox ZED-F9P](https://www.u-blox.com/en/product/zed-f9p-module) 可参考接收板和天线的分离形态，不使用其定位精度或规格作 OptiSpray 功能承诺。
- **完成条件：** 游标从所选航线起点随播放进度移动；切换章节或计划后，游标与路线回到一致状态。

#### 7. Pump & controller

- **要让访客看懂：** 通讯异常如何让控制器停止喷洒。
- **当前差距：** 这是目前较完整的硬件动画；控制器和液路已存在，但没有独立泵体模型。
- **画面与交互：** 保留现有 Locate → Isolate → Connect → Run → Interrupt → Inspect → Assemble 流程。故障阶段从 0 秒开始倒计时，三秒后液路粒子和喷嘴液滴同时停止，状态回到待机后可重播。泵体只有在找到项目实物照片或 CAD 后才加入整机；此前用现有控制器、液路线和喷嘴状态表达已支持的停止逻辑。
- **完成条件：** 倒计时到三秒与泵/喷雾停下处于同一时间线；切走再回来时无残留分离状态；不宣称机载飞行中已接入该控制器。

#### 8. Flow sensing

- **要让访客看懂：** 流量读数在液路的哪个位置被采集，以及如何传回平台。
- **当前差距：** 目前与压力入口共用喷杆高亮；没有流量计、读数变化或数据链动画。
- **建模与动画：** 在药箱到喷杆的液路关系旁新增紧凑的串接式流量部件局部视图，表现进液、流经测量段、脉冲到控制器、平台收到流量字段。若项目 Dashboard 没有本次任务的真实流量值，画面只显示信号到达，不生成 L/min 数字。流量变化不直接修改现有固定轨迹或沉积数据。
- **参考：** [ifm 液体流量传感器](https://www.ifm.com/us/en/category/200_020_030) 可参考串接式测量段和接口布局，不按工业产品尺寸推定机载规格。
- **完成条件：** 测量段能与现有药箱、喷杆在同一近景理解；不与喷嘴/轨迹数据建立未经确认的数值关系。

#### 9. Pressure & valves

- **要让访客看懂：** 压力在液路中的测量位置，以及阀门改变液路状态的方式。
- **当前差距：** 目前只有喷杆模型和文字；项目资料明确阀门控制仍需要飞机侧接入。
- **建模与动画：** 压力传感器做成独立螺纹接口与传感头，靠近喷杆分流点展示，不固定装到机体。先播放压力读数从管路接口传到 Dashboard 字段；无任务读数时不显示数值。阀门部分只进入独立拆分特写：阀芯关闭、液流停止，再打开、液流通过。该动作保持为独立部件交互，不能改变作业监看中的飞机喷雾状态。
- **参考：** [ifm PN7392](https://www.ifm.com/us/en/product/PN7392) 可参考过程接口和本体形态；[ASCO V625](https://discreteautomation.emerson.com/product/asco-v625) 可参考小型阀体与线圈结构。两者都不是项目已选型号。
- **完成条件：** 压力测量和阀门动作独立于机载执行状态；取得项目硬件位置/接入确认后才把它们加进整机装配状态。

### Precision Spraying

#### 10. Nozzles

- **要让访客看懂：** 喷嘴在喷杆上的位置，以及液滴从哪个出口开始。
- **当前差距：** 已有 7 个喷嘴和进入液滴章节的按钮；轨迹数据没有喷嘴 ID，目前靠数组序号轮换匹配出口。
- **画面与交互：** 镜头先显示整条喷杆，再逐个扫过现有喷嘴，最后聚焦一个出口并接到其实际轨迹记录。先根据轨迹的释放坐标和时间核验出口映射。若现有记录无法恢复逐出口关系，就改成显示整条喷杆产生的轨迹分布，不把每条轨迹绑定到某个喷嘴。不要添加未有资料支持的喷角、扇形或喷嘴规格。
- **参考：** [TeeJet 喷雾技术指南](https://www.teejet.com/en-in/-/media/dam/agricultural/usa/sales-material/product-market-bulletin/li-tj416_user-guide-to-spray-technology.pdf) 可借鉴喷嘴到喷幅的说明画法；实际喷形仍由项目喷嘴资料决定。
- **完成条件：** 喷嘴、轨迹、落点在同一镜头链条中能连续辨认；不再使用数组序号作为喷嘴来源。

#### 11. Droplet flight

- 播放顺序为喷口、液滴飞行、漂移特写、作业回放和沉积。首个喷洒航段从 `tracks.bin` 读取已有轨迹。尾迹跟到当前液滴，液滴落地后已走过的线短暂淡出。
- 漂移特写沿用官网 Physics 的 `physics.json` 样本和侧视取景。画面标出释放点、落点、顺风方向和样本的顺风距离。最后拉到整田画面，用橙色标出下风侧田界，用蓝色显示同一北向方案的沉积。
- 作业回放使用南北向 Plan A。画面和地图读取同一案例时间，并留出时间看清首个转场中的停喷状态。

#### 冠层沉积

- 冠层沉积在 Droplet flight 的最后展示。液体沉积来自 `landings.bin` 和现有栅格计算，地图和三维场景共用这批落点。

### Digital Platform

#### 13. Operation workflow

- 田边操作员手持平板的画面开场。作业前、作业中和作业后三张卡片同页显示，依次放大截图中的重点并更新底部说明。
- 作业前自动演示南北向 Plan A 的选中效果。作业中依次高亮航段进度、喷洒状态与漂移图层。作业后依次显示报告、阈值、导出和历史记录。

#### 14. Flight planning

- 用官网 Field Route 的两张截图解释同一田块的风况比较。先高亮风速和风向输入，再分别高亮西风下的东西向和北风下的南北向。两个场景风速均为 4.6 m/s。
- 两张截图显示风向、候选航向和田外质量比较。随后用 AeroGuard 的候选方案截图演示选中南北向 Plan A。

#### 15. Operation monitor

- 用 Dashboard 作业回放截图依次高亮航段进度、喷洒状态、沉积与漂移图层。实线表示喷洒，虚线表示停喷转场。漂移步骤定位到下风侧田界。
- 右侧地图和飞机的位置在 Droplet flight 中同步播放，数字平台卡片用截图解释地图功能。

#### 16. Operation report

- 截图依次突出田内外示踪剂、按质量加权的第 95 百分位漂移距离、安全阈值、打印或保存 PDF，以及从历史打开报告。
- 报告摘要与历史截图使用同一条 Skagit 保存记录。

### Connected Services

#### 17. Connected Services

- **要让访客看懂：** 当前资料中有哪些田间作业、种植者协作和研究/集成方向。
- **当前差距：** 有三类服务说明，但没有服务流程或明确后续入口。
- **画面与交互：** 三张卡分别关联已有 Dashboard 作业流程、当前合作/伙伴内容、网站 Research 页面。每张卡展示“进入—查看—回到产品体验”的短路径。联系入口使用网站已经存在的合作资料下载，不新建预约、售后或远程运维能力。
- **完成条件：** 每个服务卡都连接到现有页面或资料；不出现没有资料支撑的服务承诺。

### Pricing

#### 18. Pricing

- **要让访客看懂：** 官网现有两项价格分别对应的计价单位。
- **当前差距：** 官网已有硬件 RMB 1,980/台、软件 RMB 299/台/年；没有产品包、适配条件、服务范围或购买路径资料。
- **画面与交互：** 按官网现有内容并排展示硬件和软件价格卡，价格旁保留清楚的计价单位；下方链接既有合作资料入口。不增加未提供的套餐、税费、安装或售后内容。
- **完成条件：** 金额、币种、计价单位与官网一致；价格区域不出现 “planned” 或 “planning” 字样，不添加未经网站资料支持的购买承诺。

## 建议的播放时间线

时长仅控制观看节奏，不改变案例里的任务时长、传感器读数、轨迹或沉积结果。观众随时可以暂停、跳到步骤或重置。文字只在右上信息卡和左侧步骤条更新。

| 入口 | 推荐步骤与时间 | 交互方式 |
| --- | --- | --- |
| Overview | 12 秒：全景 2 秒 → 环境 2 秒 → 航线 2 秒 → 喷洒 3 秒 → 沉积 2 秒 → 报告入口 1 秒 | 可暂停；点击任一步跳进对应菜单。 |
| Product advantages | 不自动播放；三个卡片逐个聚焦 | 点击卡片进入对应数据章节。 |
| Wind sensor | 11 秒：整机 1.4 → 分离 1.8 → 测风 3 → RS485 3 → 复位 1.8 | 复用当前步骤时间线，增加风向视图。 |
| Temperature & humidity | 7 秒：定位 1.2 → 拆分 1.5 → 读数 2.5 → 传递 1.8 | 读数固定使用案例值。 |
| Light sensing | 5 秒：定位 1 → 光线进入 1.5 → 数据传递 1.5 → 复位 1 | 不造照度读数。 |

## 无现成模型时的建模规则

新部件沿用现有程序化机体的局部坐标、材质和拆分动画。在功能特写中以独立 Three.js Group 展示，可由“整机位置—部件分离—部件近景—功能路径—复位”构成；不需要外部下载飞机模型，也不改变现有无人机轮廓。

| 部件 | 建议几何 | 动画重点 | 位置约束 |
| --- | --- | --- | --- |
| 温湿度 | 小型电路板、带通气孔的外罩、单独的连接端 | 环境信息进入外罩，读数流向 Dashboard 环境卡 | 暂不装到机体；没有安装依据。 |
| 照度 | 小型板件和面向外部的光学开口 | 光线到开口，再沿数据线到照度字段 | 不添加照度数值或阈值。 |
| GPS | 高亮现有定位接收部件 | 位置输出游标沿所选路线更新 | 不显示实机位置误差或精度。 |
| 流量 | 液路中串接的短筒、入口/出口、侧接头 | 液体通过测量段，数据脉冲沿线传回 | 具体串接位置待实物或管路资料确认。 |
| 压力 | 螺纹接口、传感头、顶部电连接 | 压力信息从液路接口传到字段 | 不设置项目没有的读数。 |
| 阀门 | 阀体与线圈/执行端分组 | 只在独立部件视图显示关闭和通过两状态 | 机载阀门位置及控制未确认前，不连接到作业状态。 |
| 泵 | 电机壳体与泵头分组 | 控制器运行/失联与液路停止共用时间线 | 先找项目泵实物；没有实物资料时不把通用外形装到飞机。 |

这些形态参考只用于尺寸关系和结构表达，不等于 OptiSpray 已选择该型号。最终页面不添加来源边界标签；如果某部件的真实安装位置尚未确定，就保留为章节内的局部部件查看，不放进整机完成状态。

## 状态、镜头与互动的执行规则

1. **同一任务状态：** Dashboard 是规划、阶段与报告的唯一任务来源；产品页读取已选路线、阶段、进度，驱动 3D 飞机和已有数据层。不要再建一份独立的产品页航线状态。
2. **统一时间轴：** 风传感器、泵控、液滴和沉积各自有步骤时间轴，提供播放、暂停、逐步选择、重播、重置。操作 Dashboard 的章节按原平台交互，不显示虚假的产品页播放条。
3. **可恢复切换：** 切章时停止旧时间轴、清理高亮和分离状态。再进入时按该章规定的起始状态初始化。快速切换检查覆盖风传感器 → 液滴 → Dashboard → 泵控 → 返回风传感器。
4. **镜头层级：** 整机全景负责上下文；中景说明部件位置；近景说明接口和动作；田块鸟瞰说明航线与沉积。标题、章节说明和当前步骤固定在右上信息卡，不跟随无人机漂移；被说明的设备在场景内保持高亮定位。
5. **数据驱动画面：** 飞机路线来自同一 Plan；液滴位置来自当前案例轨迹；沉积来自同一案例落点。缺少对应数据时留空或停留在部件关系动画，不生成另一套数字。
6. **离线一致性：** 新功能和新增模型应进入 Vite 构建与 scripts/package-offline.ps1；每次更新离线包后核对启动脚本、Dashboard、轨迹、落点、航拍及环境文件。

## 逐项验收标准

- 18 个入口都能说出“看什么、怎么动、链接到哪个项目内容”，不再有只换文字标题的重复章节。
- 无人机总览保持现有外观；每个新部件形态有项目资料或官方形态参考，未确认安装位置的部件只在局部视图出现。
- 液滴画面可看清出口、路径和落点；沉积图与相同播放时钟同步；Plan B 不显示缺失的沉积数据。
- 任务规划、作业中、报告和历史指向同一项任务；存档能恢复完整任务资料。
- 左侧菜单可纵向滚动；标题和步骤说明固定在右上信息卡，硬件名称与用途对应到被高亮的设备，不遮挡菜单按钮或喷雾主体。
- 开发预览与离线包引用同一份网站、Dashboard 和 Skagit 核心资源。

## 已确定的实施原则

1. 温湿度、照度、GPS、流量、压力、泵和阀门先做局部可拆分部件，材质与现有无人机保持一致；随后复用网站已有拆解/回装动画，将部件装回场景中的无人机装配关系。
2. AeroGuard Dashboard 是任务、阶段、航线和报告状态的唯一来源；产品页只同步三维场景。
3. 作业界面使用田边固定智慧大屏，屏幕位于田块边缘并朝向观看者；不增加人物模型。
4. 喷洒使用官网现有任务时钟、`pointAt()` 插值、七个实体喷嘴出口和轨迹顺序；展示喷杆整体喷洒，不新增逐轨迹喷嘴编号。
5. 价格使用官网现有硬件 RMB 1,980/台、软件 RMB 299/台/年；价格区域不出现 “planned” 或 “planning” 字样。
